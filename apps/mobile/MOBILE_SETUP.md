# Raja Rani — Mobile App Setup

## Important: one step you need to run that I couldn't

This `apps/mobile` folder has the app's Dart source code (`lib/`), but it's
**missing the `android/`, `ios/`, and other platform folders** that
`flutter create` normally generates — those are thousands of files of
platform boilerplate (Gradle config, Xcode project, generated plugin
registration) that only the Flutter SDK itself can produce correctly, and
this environment doesn't have the Flutter SDK installed.

**Before you can run this app, do this once:**

```bash
cd apps/mobile
flutter create --org com.rajarani --project-name raja_rani .
```

Run this **in the existing `apps/mobile` folder** (note the trailing `.`) —
it fills in the missing platform folders around the `lib/` and
`pubspec.yaml` that already exist, without touching them. If it prompts
about overwriting `pubspec.yaml`, say no / keep the existing one.

## Prerequisites

- Flutter SDK (stable channel) — https://docs.flutter.dev/get-started/install
- Android Studio (for the Android SDK + an emulator, or a physical device
  with USB debugging on)
- The backend running locally — see `../../docs/SETUP_GUIDE.md` in the repo
  root first; this app talks to `http://10.0.2.2:4000` by default (the
  Android emulator's alias for your host machine's localhost)

Verify:
```bash
flutter doctor
```
Resolve anything it flags before continuing.

## Install and run

```bash
cd apps/mobile
flutter pub get
flutter run
```

Pick an emulator or connected device when prompted. First launch shows the
splash screen, then routes to login (no session yet).

## Try it end-to-end

1. Tap "Don't have an account? Sign up", register with any email — this
   calls the real `POST /api/v1/auth/register` you set up in the backend
   guide.
2. You land on Home. If your backend has the seed data
   (`npm run seed` in `services/api`), you'll see the two seeded courses.
3. Tap the free course → "Enroll for Free" → check the Library tab.
4. Tap the paid course → "Buy Now" — this creates a real Order via the
   Razorpay-backed endpoint (see repo-root `docs/PAYMENTS.md`); actually
   opening the Razorpay checkout UI is the next mobile phase (needs the
   `razorpay_flutter` package + your live/test Razorpay key).

## Pointing at a different backend

```bash
flutter run --dart-define=API_BASE_URL=https://your-staging-api.example.com
```
See `lib/core/network/env.dart`.

## Google Sign-In setup

"Continue with Google" on the login screen needs real configuration
before it works — without it, tapping the button fails with a clear
platform-level error rather than silently doing nothing:

1. In Google Cloud Console, create an OAuth 2.0 Client ID (type: Android,
   using this app's package name and SHA-1 signing certificate — `flutter
   create` generates a debug one automatically for local testing).
2. Also create a **Web** client ID in the same project — this is the one
   that goes in the backend's `GOOGLE_CLIENT_ID` (`services/api/.env`),
   since ID token verification checks against that audience.
3. Download `google-services.json` from Firebase/Google Cloud Console and
   place it at `android/app/google-services.json` (generated by `flutter
   create`, not committed to this repo — see the root `.gitignore`).

## What's built vs not (this phase)

**Built:** splash, login, register, OTP login, home (banners + continue
learning + course list, all from real endpoints), course details (with the
brief's exact CTA logic — Enroll/Buy Now/Continue Learning), library (with
real progress), account screen shell, bottom-nav shell (Home/Library/
Community/Account), secure token storage, automatic 401-refresh.

**Not built yet:** the actual lesson video player (backend's
`playback-token` endpoint exists, the player screen consuming it doesn't),
Razorpay checkout UI, community feed screen, certificates screen, live
class screens, search screen, onboarding, push notification wiring
(Firebase project needed), and — importantly — no automated tests for any
of this yet.
